CareerQuest 문제점 · 수정할 부분 목록
=====================================
- 코드 수정이나 테스트 중에 발견한 문제를 여기에 적는다.
- 고친 항목은 제목 옆에 (해결)을 붙이고, 어떻게 고쳤는지 한 줄 남긴다.
- 번호는 재사용하지 않는다. 새 항목은 맨 아래에 추가한다.


[1] 네이버 요약(snippet)이 잘려서 핵심 근거가 빠짐
  - 발견: 2026-10-29, 요구사항 검색 테스트 (피지컬 AI 엔지니어, 검색어 5개)
  - 위치: engine/tools/naver.py
  - 내용: 실제 채용공고(제논·뉴빌리티·케어링·퀘스터 등)는 대부분 네이버 카페 결과였는데,
          본문을 수집하지 않으니 우대사항이 "…"로 잘린다. 가장 쓸모 있는 근거가 snippet 수준에 머무름.
  - 메모: 네이버 robots.txt 정책상 본문 수집은 불가. 같은 공고를 원문(기업 채용 페이지 등)에서
          다시 찾는 방법을 검토해야 함.

[2] 본문 수집 대상 중 주제와 무관한 문서가 많음
  - 발견: 2026-10-29, 요구사항 검색 테스트
  - 위치: engine/tools/requirements.py (collect_candidates → fetch_texts 사이)
  - 내용: 본문을 수집한 카카오 문서 22건 중 요구·우대사항을 직접 담은 건 4~5건.
          나머지는 투자 뉴스, 정책 예산, 창업 인터뷰 등. 검색 순위 그대로 앞에서부터 수집하기 때문.
  - 메모: 재정렬 모델을 두 단계 사이에 넣어 title + snippet으로 순서를 다시 매긴 뒤 수집.

[3] 본문 추출 결과에 페이지 잡음이 섞임
  - 발견: 2026-10-29, 요구사항 검색 테스트
  - 위치: engine/tools/crawl.py (_extract)
  - 내용: LLM이 본문 전체를 읽으므로 그대로 토큰 낭비가 된다.
          - bbs.ruliweb.com: 기사 뒤에 사이트 메뉴·댓글 목록 약 200줄
          - www.gukbi.com: 빈 표 줄("| |")이 수십 줄 반복
          - blogger5526.tistory.com: 단어 하나가 한 줄씩 끊겨 추출됨 (티스토리 셀렉터 경로)
  - 메모: 본문 일부를 골라내는 것이 아니라 추출 품질 문제. 사이트 잡음 제거·줄 합치기로 접근.

[4] 네이버 웹문서(webkr)도 무조건 본문 수집 안 함
  - 발견: 2026-10-29, 코드 확인
  - 위치: engine/tools/naver.py (fetch_status="skipped" 고정)
  - 내용: 네이버 블로그·카페는 naver.com 도메인이라 수집 금지가 맞지만, webkr 결과는 외부 도메인인데도
          전부 skipped 처리된다. kakao.py처럼 precheck_status로 판단하면 수집 가능한 문서가 생길 수 있음.

[5] 검색어가 달라도 같은 문서가 반복해서 수집됨
  - 발견: 2026-10-29, 요구사항 검색 테스트 (본문 25건 중 고유 문서 22건)
  - 위치: engine/tools/requirements.py
  - 내용: 중복 제거가 한 번의 호출 안에서만 된다. 같은 직무로 여러 번 검색하면 같은 문서를 다시
          받고(요청 간격 2초씩 소모), LLM도 같은 본문을 다시 읽게 됨.
  - 메모: README의 "문서별 근거 카드 캐시"(SQLite)와 함께 doc_id 기준 캐시로 해결.

[6] LLM에게 보여 줄 도구 결과 형식이 정해지지 않음
  - 발견: 2026-10-29, 요구사항 검색 도구 구현
  - 위치: engine/tools/requirements.py (RequirementSearchResult)
  - 내용: 지금은 pydantic 객체를 그대로 반환. 도구 호출 결과로 LLM에 넘길 텍스트 형식
          (문서 목록·본문·출처 표기)은 모델·프롬프트 확정 후 파이프라인 단계에서 정해야 함.
