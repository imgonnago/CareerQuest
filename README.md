# CareerQuest AI

> 대학생 맞춤형 취업 준비 로드맵 — 대전 지역 대학·성장자원 연계 기반
>
> 학생의 전공·학년·보유 역량·희망 직무를 입력받아, 직무가 요구하는 역량과 비교하고

주요 출처: `konyang.ac.kr` · `q-net.or.kr` · `dataq.or.kr` · `daejeonyouthportal.kr` · `djrise.or.kr` · `jobkorea.co.kr` · `saramin.co.kr` · `job.alio.go.kr`

### 데이터 수집 파이프라인

```
1. 검색 ─▶ 2. 원문 확보 ─▶ 3. 정리 ─▶ 4. Resource 통합 ─▶ 5. 저장
검색 API     공식 페이지      불필요 내용     교과목·자격증·프로그램·    DB 저장
             본문 수집        제거·중복 제거   채용공고를 공통 형식으로   → 추천·검색·RAG에 활용
```

### Skill 매핑

```
1. 원문 입력 ─▶ 2. Skill 후보 추출 ─▶ 3. 사전 매칭 ─▶ 4. 관계 부여 ─▶ 5. DB 저장
채용공고·교과목    LLM이 문장에서       미리 정의한        필수/우대/학습     RESOURCE_SKILL
자격증·학생 경험   핵심 기술 추출       공통 Skill과 연결   검증/관련/경험
```

예: `"Spring Boot 기반 서버 개발 경험 우대"` → `Spring / Backend / PREFERRED`

### DB 구조

```
STUDENT ─1:N─ STUDENT_SKILL ─N:1─ SKILL ─1:N─ RESOURCE_SKILL ─N:1─ RESOURCE
```

| 테이블 | 주요 필드 |
|---|---|
| `STUDENT` | student_id, school, major, grade |
| `SKILL` | skill_id, skill_name, category, description |
| `STUDENT_SKILL` | student_skill_id, student_id, skill_id, evidence, level |
| `RESOURCE` | resource_id, type, name, description, organization, url |
| `RESOURCE_SKILL` | resource_skill_id, resource_id, skill_id, relation_type |

- `RESOURCE.type`: 교과목 / 자격증 / 대전 프로그램 / 채용공고
- `relation_type`: 필수 · 우대 · 학습 · 검증 · 관련 · 경험

## 🤖 3. 분석 · 추천 엔진 (LLM) — 조용재

### 왜 에이전트인가

고정 RAG는 미리 구축한 벡터 DB 안에서만 답하므로, DB에 없는 기업·직무·최신 정보에 답하지 못함
→ **LLM이 근거가 부족하다고 판단하면 검색 API 등 도구를 직접 골라 근거를 보충**

- **LLM:** 도구 선택 · 문서 읽기 · 판단
- **코드:** 도구 실행 · 저장 · 세기 · 검증 (8B 모델의 약점 보완)

### 실행 흐름 (5단계)

```
(1) 목표 직무 설정 ─▶ (2) 근거 추출 ─▶ (3) 근거 집계 ─▶ (4) 우선순위 판단 ─▶ (5) 검증
      LLM            LLM ↔ 도구 루프      코드 + LLM          LLM               코드
                    (체크리스트 충족까지)                                 판단 오류 → (4)
                                                                         근거 부족 → (2)
```

| 단계 | 담당 | 입력 → 출력 |
|---|---|---|
| (1) 목표 직무 설정 | LLM | 학생 입력 → 표준 직무 JSON (Skill DB 직무 목록에서 선택, 없으면 검색으로 보완) |
| (2) 근거 추출 | LLM + 코드 | 직무 JSON → **근거 풀**(원문) + **상세 근거 카드** |
| (3) 근거 집계 | 코드 + LLM | 상세 근거 카드 → **근거 집계 표** (Skill + 역할별, Gap 포함) |
| (4) 우선순위 판단 | LLM | 근거 집계 표 + 프로필 → **근거 순위 카드** |
| (5) 검증 | 코드 | 근거 순위 카드 ↔ 원문 대조, 마감일·개설학기 확인 |
| 결과 생성 | LLM | 검증 통과 순위 + (doc_id, Skill)로 찾은 상세 근거 카드 → 최종 답변 |

### 에이전트 도구

| 도구 | 내용 |
|---|---|
| RAG 검색 | 건양대 교육과정 · 로드맵 · 수업계획서 · NCS → 공식 근거 |
| 요구사항 검색 | 네이버 · 카카오 검색 API → 합격 후기 · 우대사항 · 자격증 정보 |
| 채용공고 조회 | 사람인 · 고용24 등 → 현재 모집 중 공고 |
| 공모전 · 대회 검색 | 검색 API로 링커리어 공모전 · 대회 → **링크만 제공** |
| (선택) GitHub 검색 | 개발 직군 참고 프로젝트 |

### 산출물 이름

| 이름 | 단계 | 원문 포함 |
|---|---|---|
| 근거 풀 | (2) | 원문 전체 |
| 상세 근거 카드 | (2) | 근거가 된 원문 문장(인용) |
| 근거 집계 표 | (3) | ✗ (숫자 · 근거 번호) |
| 근거 순위 카드 | (4) | ✗ (순위 · 행동 · 근거 번호) |

## ⚖️ 데이터 수집 원칙

- 우선순위: **API → 크롤링(robots.txt · 이용약관 확인한 사이트만) → 수작업**
- 채용 플랫폼(링커리어 · 잡코리아 · 캐치 등) 상세 페이지는 크롤링하지 않고 **링크만 제공**
- 기업 채용 사이트 내용은 사실 항목 요약 + 출처 링크로만 사용
- 합격 자소서는 수집하지 않음
- **API 키는 `.env`에 보관하고 절대 커밋하지 않기** (`.gitignore`에 `.env` 추가)

```
# .env.example
NAVER_CLIENT_ID=
NAVER_CLIENT_SECRET=
KAKAO_REST_API_KEY=
SARAMIN_API_KEY=
WORK24_API_KEY=
DATA_GO_KR_API_KEY=
GITHUB_TOKEN=
```
